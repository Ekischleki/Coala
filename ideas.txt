Quality of life (No major changes to atom tree architecture):

    Optional types at compile time. If you set a field of a composite type to be optional, you don't necessarily have to define it when creating the Composite type.

    Outputs. They'd use the value action infrastructure to output debug messages displaying a string and a value

    Variable scoping. Disallows stuff like this
    if condition {
        let a = false
    } 
    #Usage of a 

    Reassigning variables within branches by using something like a selector of the variable value if the condition was met or not.
    By not so similar reasoning, we could also allow reassigning variables within the same scope by simply replacing what it references.
    Also kinda related:
    Early returns for functions. Would require something similar to how conditionals are implemented.

    Arrays and loops. Both of them would have to be rolled out, and are basically just macros making batch operations easier.

Optimization
    How to deal with inlining
    1. Inline all variables
    2. Simplify
    3. Extract the biggest equal parts into variables
    If a variable is inserted and then simplified (Variables would only simplify outwards), then the outer most levels of simplification will make the inlined statement shallower by n, while the rest of the structure will still stay in tact.
    This means that this pipeline will never increase the size of a graph.

Architecture features are optional features an architecture may support. These features may not be emulated by other features and
can be specified to be added to a project. The minimal project requires to support the following:
Fixed program runtime. The project has to run in a deterministic runtime, meaning recursion and true loops are not supported, but can be emulated through unrolling.
Fixed input: The project takes a fixed sized input, determined at compiletime through the problem solution architecture. Booleans: The project must support booleans and a functional set of boolean operations. Missing operations can be emulated by the given functional set.
Given these features, the standart library contains a set of features that implement collections like Integers, though these can be explicitly implemented by the architecture, which may result in faster runtimes and smaller compilations.
Overwritable features:
    Assigns: Variable assigns may differ from architecture to architecture. Per default the compiler assumes that variable assigning doesn't exist and recreates the operations needed to create the variable from the input every time it is copied. 
        Mutability is also not assumed. Variables are simply shadowed per default when reassigned. If there's a conditional reassign, the variable is shadowed with a selector function selecting between all branches given their condition.

Optional features:
    Asserts:
        The application supports assertations, which is code that stops all execution (or similar) at runtime if a boolean value, given as its input, is true. The assertation may also be provided with a string representing an error, though it is optional for the architecture to actually use it.
